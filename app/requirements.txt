# ===============================================================================
# WiSAR Terrain-Aware Range Rings — Python dependencies
#
# Captured from the production venv on sar.weleber.net with `pip freeze`, so
# these are the versions the tool is known to run on rather than a wish list.
#
# Until this file existed, the environment lived ONLY inside the venv on the
# server: a rebuild would have produced no virtualenv and the service would not
# have started. weleber-server-config/provision.sh phase 50 looks for exactly
# this path (app/requirements.txt).
#
# System packages this stack needs, installed by provision.sh phase 10 and NOT
# installable with pip: gdal-bin, libgdal-dev, python3-gdal, libspatialindex-dev.
# osmium-tool is required by tools/build_osm_cache.py, not by the web app.
#
# Versions are pinned exactly. The geospatial stack is tightly coupled --
# rasterio, geopandas, pyogrio and fiona all bind the same GDAL, and a partial
# upgrade produces import-time failures rather than a clean error. Upgrade the
# set together, on a rebuilt venv, and run a real analysis before deploying.
# ===============================================================================

# Numerics. scipy supplies convolve2d, binary_dilation and uniform_filter for

# Raster-to-PNG rendering for the overlay endpoints.

pyarrow==24.0.0
